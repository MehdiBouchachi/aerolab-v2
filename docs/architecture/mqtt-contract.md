# MQTT device contract v1 (implemented)

Authoritative artefacts: JSON Schemas `contracts/mqtt/schemas/*.schema.json`, Go validators
`contracts/mqtt/*.go`, fixtures `contracts/examples/{valid,invalid,invalid-semantic}`.
`go test ./contracts/mqtt` proves the schema and the Go code give the **same verdict on every fixture**
(it already caught one drift while this was written). Firmware and TypeScript must be generated from /
validated against the same files.

## Topics (`aerolab/v1/devices/{deviceId}/…`)

| Leaf | Direction | QoS | Retained | Persistence on the Pi |
|---|---|---|---|---|
| `presence` | device → Pi (birth + Last Will) | 1 | yes | memory only; never proves liveness |
| `state` | device → Pi, every 5 s | 0 | no | memory; only *transitions* reach SQLite |
| `telemetry` | device → Pi, 60 s + replay | 1 | no | `telemetry_snapshots` (durable, deduped) |
| `events` | device → Pi | 1 | no | `device_events` (durable, deduped) |
| `commands` | Pi → device | 1 | **never** | `commands` table |
| `command-results` | device → Pi | 1 | no | updates `commands` |
| `receipts` | Pi → device | 1 | no | – |

IDs match `^[a-z0-9][a-z0-9-]{2,39}$` (no wildcard characters can enter a topic or an ACL).
Payload ≤ 8 KiB, JSON depth ≤ 8, `schema_version` must be 1 (anything else is rejected explicitly).
Unknown extra fields are tolerated (additive evolution within v1); unknown sensor names are stored.

## Rules enforced by code

* **Receipt = durable.** Records are `INSERT OR IGNORE`d in one SQLite transaction (`synchronous=FULL`);
  only after COMMIT the Pi publishes `{acked_sequences,…}`. A device frees flash **only** on a receipt,
  never on PUBACK. Duplicates (same `device_id,boot_id,seq`) are stored once and re-acknowledged.
  A poisoned record (valid identity, invalid content) gets `rejected_sequences` so it is not resent forever.
* **Honest time.** `monotonic_only` devices MUST send `sampled_at_utc: null`; a timestamp there is
  `FABRICATED_TIMESTAMP`. The Pi stores the original fields untouched plus `effective_at_utc` with
  `time_quality` = `DEVICE_CLOCK | ESTIMATED_FROM_UPTIME | RECEIVED_AT_ONLY`.
* **Missing ≠ 0.** `missing` readings must have `value: null`; `valid` readings must carry a value.
* **Commands are session-bound.** Each MQTT connection has a random `session_nonce` (in `presence` and
  `state`). A command carrying another nonce is `REJECTED/STALE_SESSION`, so a command parked in the broker
  across a reconnect can never execute later. Commands also carry `ttl_seconds` and an expiry, an
  `expected_program_version` (optimistic concurrency, `new = expected+1`) and an idempotency `command_id`.
  Devices keep the last 32 outcomes; a repeat returns `ALREADY_PROCESSED` + `original_status`.
* **Protection cannot be configured away.** `require_reservoir_ok:false` is invalid in the schema, the Go
  validator, the Pi API **and** the simulated firmware. Each board additionally enforces its own hard
  maximum ON time. Manual pump tests are not a command type: they are local-only by design.
* **Source honesty.** Every device message carries `data_source` (`DEVICE`|`SIMULATOR`); the Pi refuses a
  device whose declared source differs from its registration, and refuses SIMULATOR data entirely unless
  `AEROLAB_ALLOW_SIMULATED_DATA=true`.

## Cross-field rules JSON Schema cannot express (Go-validated, fixtures in `invalid-semantic/`)

`max_continuous_on_seconds ≥ on_duration_seconds`; `new_program_version == expected_program_version + 1`.
Firmware must implement these too.

## Broker security (as generated by `aerolab-seed`)

`allow_anonymous false`; one account per device (PBKDF2-SHA512); a single static ACL using `%u`:
device may *write* only its own `presence|state|telemetry|events|command-results` and *read* only its own
`commands|receipts`; the `aerolab-edge` account reads all uploads and writes commands/receipts.
Verified against a real Mosquitto 2.0.18 by `TestA25_…` (behaviourally: note Mosquitto 2.0 over MQTT 3.1.1
acknowledges a denied SUBSCRIBE but never delivers, so isolation is asserted on delivery).
Dev listeners are plain MQTT on loopback. TLS is **not** implemented/verified yet.
